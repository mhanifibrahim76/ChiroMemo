# Database

Provider: **Supabase Postgres** · ORM: **Prisma 7** · Schema: `prisma/schema.prisma`
· Config: `prisma.config.ts` · Migrations: `prisma/migrations`
· Client: `src/lib/db.ts` · Generated client: `src/generated/prisma` (git-ignored,
regenerated by `npm run db:generate` / `postinstall`).

> Status: **schema implemented and migration SQL generated, but not applied to a
> live database.** No Supabase credentials were available, so `prisma migrate dev`
> could not run. Applying the migration is the first task of the next session that
> has a connection string. See "Migration status".

## Prisma 7 specifics (do not copy Prisma 6 tutorials)

Prisma 7 changed several things that break older guides:

| Concern            | Prisma 6 and older                       | Prisma 7 (this project)                          |
| ------------------ | ---------------------------------------- | ------------------------------------------------ |
| Config file        | none (schema only)                       | `prisma.config.ts` at the project root           |
| Env loading        | Prisma CLI loaded `.env` automatically   | config file calls `dotenv` explicitly            |
| Datasource url     | `url = env("DATABASE_URL")` in schema    | `datasource.url` in `prisma.config.ts` only      |
| Generator          | `prisma-client-js`                       | `prisma-client`, `output` is required            |
| Client output      | `node_modules/.prisma/client`            | generated TypeScript in the project (`src/`)     |
| Runtime engine     | Rust query engine binary                 | WASM query compiler + **required driver adapter** |
| Connection string  | passed to `PrismaClient`                 | passed to the driver adapter in application code |

Runtime client construction (Prisma 7 has no `datasourceUrl` option):

```ts
import { PrismaPg } from "@prisma/adapter-pg";
import { PrismaClient } from "@/generated/prisma/client";

const prisma = new PrismaClient({ adapter: new PrismaPg({ connectionString }) });
```

## Connecting to Supabase

- Use the **Direct connection** (port 5432) or the **Session pooler** (port 5432)
  for Prisma. Do not use the **transaction pooler** (port 6543) for migrations.
- `DATABASE_URL` is read from `.env.local` (Next.js) and by the Prisma CLI through
  `dotenv` inside `prisma.config.ts`, so one local file serves both.
- The generated client uses extensionless ESM imports, so it is resolved by the
  Next.js bundler. Do not import it from a plain Node script.

## Migration status

- `prisma/migrations/20260930000000_init/migration.sql` — **generated and reviewed,
  NOT applied.** It was produced with `prisma migrate diff --from-empty` (a
  read-only command) because no database connection was available.
- Applying it requires a real `DATABASE_URL`:

```bash
npm run db:deploy   # prisma migrate deploy — applies existing migrations
```

  or, for local development, `npm run db:migrate` (`prisma migrate dev`), which
  will apply the existing init migration first and then detect further changes.

## Relationship summary

```
User
 ├─ 1:N ─ LearningGoal ─ 1:N ─ Roadmap ─ 1:N ─ RoadmapStep
 ├─ 1:N ─ Resource ─ 1:N ─ Note
 │        └────── 1:N ─ Summary
 └─ 1:N ─ LearningActivity
```

## Conventions

- `id`: `cuid()` except `User.id`, which is the Supabase Auth uuid string.
- All user-owned rows carry `userId`; every query filters on it.
- Timestamps: `createdAt`, `updatedAt` (`@updatedAt`).
- Deleting a `User` cascades; deleting a `Resource` sets `Note.resourceId` and
  `Summary.resourceId` to null so notes/summaries survive.
- `progressPercent` on `Roadmap` is derived from step statuses; recomputed by the
  server on step updates (Phase 5).

## Commands

```bash
npm run db:validate   # prisma validate
npm run db:generate   # prisma generate -> src/generated/prisma
npm run db:migrate    # prisma migrate dev   (local development)
npm run db:deploy     # prisma migrate deploy (production / applying init)
npm run db:studio     # prisma studio
```

`prisma generate` does not need `DATABASE_URL`; `migrate` and `studio` do.
